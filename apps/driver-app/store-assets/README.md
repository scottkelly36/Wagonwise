# Store and website assets

- `play-icon-512.png`, `play-feature-graphic-1024x500.png`: Google Play graphics.
- `raw/`: full-size driver-app screenshots taken on a local stack with dummy data (1080x2400, Pixel 6 emulator, dark theme, 09:41).
- `../../dashboard/store-assets/raw/`: the same for the staff portal (1440x900).
- `framed/`: the nine raw screenshots framed with a headline, 1080 x 1920, ready for Google Play. It takes up to eight, so **leave out `08-job.png`** (the company-job screen: the least about driving, and its bottom buttons are cut off by the frame); the file numbers are the order shown, and the first three are what search shows. Apple needs its own sizes (not made yet). `scripts/make-framed-screenshots.ps1` rebuilds them.
- `scripts/make-graphics.ps1`: rebuilds the icon and feature graphic.
- `scripts/make-web-images.ps1`: crops and compresses the raw screenshots into `sites/landing/img/` as JPEGs. Then run `sites/make-webp.ps1`, which turns them into the WebP files the landing page serves and removes the JPEGs. Not re-run since the 2026-11-04 retake, so the landing page still shows the older screens.

All screenshots use made-up data (fictional firm, example emails). Scripts are Windows PowerShell and expect the repo at `E:\projects\wagonwise`.

## Retaking them (last done 2026-11-04, from `main` at `c462742`, after the compass and Keep-button fixes)

Retake whenever the app's screens change: the shots show whatever JavaScript Metro serves, so run Metro from a checkout of current `main`, not an old branch. Faster-route offer, in practice: seed the congestion report, plan Hexham to Gateshead from the A69 east of Hexham, start the trip, step the GPS about 40 points along the road, then take screenshots every few seconds for a couple of minutes (the card appears about a minute in, then folds to a small chip and reappears; tap nothing). Expire the congestion report before the trip shot so the card is not in it.

Raw file to screen: `00` home map with the fuel pins, `01` trip mid-route, `02` route options, `03` hazards on the route, `04` parking card, `05` faster-route offer, `06` report a hazard, `08` job, `09` nearby fuel. (`03a-hazard-ahead-raw.png` is an older extra that is not framed and was not retaken.)

1. **Stack.** `pnpm db:up` and `pnpm db:migrate` (Postgres), Valhalla running (`docker compose -f infra/docker/compose.yml --profile valhalla up -d valhalla`), then core (`pnpm --filter @wagonwise/core dev`) and the driver BFF (`pnpm --filter @wagonwise/driver-bff dev`). No keys are needed; leave the fuel, closures and traffic keys unset so core does not fetch real data.
2. **Data** (all made up, put in by SQL, none of it in the repo): a driver `shots@example.com` with a vehicle profile "Artic 44 t" and JOB-1042 (Tynedale Depot, Hexham, to a Gateshead centre); nine fictional fuel stations with made-up diesel and petrol prices in `fuelprices.stations` and `fuelprices.prices` (names such as "Riverside Fuels", ids `shot-1` to `shot-9`, 145.9 to 153.5 p, reported 1 to 30 hours ago); a few hazards (roadworks, a tight bend, a 4.6 m low bridge) along the A69; one 7-minute congestion report on the route ahead of the vehicle (at `-1.930879 54.973789`; this is what makes the faster-route offer appear, and a bigger wait gives an implausible "saves 30 minutes"; the offer needs a saving of at least 5 minutes and 10%); and one driver-reported parking spot, "Tyne Valley Truck Stop" in Hexham, with every facility but Secure. A made-up row in `closures.closures` puts a road-closure marker on the A69 if you want one in a shot. Expire any other active hazards near the route first, or the route detours around them.
3. **App.** The app uses MapLibre native code, so it needs a development build (installed on the `Pixel_6` AVD as `com.wagonwise.driverapp`), not Expo Go. From `apps/driver-app` run `npx expo start --dev-client`, then `adb reverse tcp:8081 tcp:8081`, then open `exp+wagonwise-driver-app://expo-development-client/?url=http%3A%2F%2F10.0.2.2%3A8081` on the emulator. Turn off the dev client's floating tools button (developer menu, Tools button off) and dismiss its first-run notice, or a grey gear sits over every shot. Sign in with the code core prints to its console, accept the privacy screen and skip the first-run walkthrough. Use the dark theme.
4. **Clean phone.** Clock 09:41, full battery and wifi, no notifications: `adb shell settings put global sysui_demo_allowed 1`, then `adb shell am broadcast -a com.android.systemui.demo -e command clock -e hhmm 0941` (also `battery`, `network`, `notifications`; finish with `-e command exit`). Set the position with `adb emu geo fix <lon> <lat>` (Hexham is `-2.1040 54.9732`); for a trip, step the fix along the route's points a second apart so the app gets a heading.
5. **Shoot.** `adb exec-out screencap -p > raw/<name>.png`, save over the files in `raw/`, run `scripts/make-framed-screenshots.ps1`, and look at every framed image for real names, plates, companies or addresses (labels and brand names that come from the map itself are fine), a stray dev-client button, and anything cut off.
